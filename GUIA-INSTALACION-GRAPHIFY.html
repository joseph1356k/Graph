Guía de instalación · Windows

graphify + Obsidian

Dos herramientas que trabajan juntas. Al terminar vas a poder preguntarle a la IA “¿dónde se maneja el audio?” y recibir archivos y líneas exactas — y navegar todo el proyecto como un mapa visual. Tiempo estimado: 15 minutos.

graphify

El motor. Analiza el código y arma un mapa de qué existe y cómo se conecta. Es lo esencial — sin esto no hay nada.

Obsidian

El visor. Convierte ese mapa en algo navegable con clics, y te deja escribir tus propias notas encima. Es opcional.

Buena noticia: el mapa ya está hecho y subido al repo. No necesitas API key ni escanear nada — con un git pull te llega listo.

Cómo quedamos conectados

Esta es la parte que más confunde, así que va primero. No hay servidor, ni cuenta compartida, ni carpeta sincronizada. La conexión es git — la misma que ya usas para el código.

GitHub
el repo de siempre

Tu compañero

El mapa (graph.json) es un archivo más del repo, igual que un .js o un .md. Viaja exactamente igual que el código: quien hace push lo sube, quien hace pull lo recibe.

Qué se comparteCómo
El mapa del proyectoPor git, dentro del repo — llega solo con git pull
La configuración de ClaudePor git (CLAUDE.md) — se hereda sin tocar nada
Los hooks de gitNo se comparten. Viven en .git/, que nunca se sube. Por eso cada persona corre graphify hook install una vez
La bóveda de ObsidianNo se comparte. Cada quien la genera desde el mismo mapa, así que sale idéntica
En una frase: el conocimiento del proyecto ahora viaja con el código. Nadie tiene que acordarse de actualizar nada, ni de avisarle a nadie.

Parte 1 — graphify

pasos 1–5
01

Verificar Python

python --version

Necesitas 3.10 o superior. Si no aparece nada, instálalo desde python.org y marca la casilla “Add Python to PATH” durante la instalación.

02

Instalar uv

pip install uv
Cierra la terminal y abre una nueva. Windows solo detecta los comandos nuevos al abrir una terminal fresca. Si te saltas esto, el paso 3 falla con “uv no se reconoce”.
03

Instalar graphify

uv tool install graphifyy

Ojo con el nombre: el paquete es graphifyy con doble y. El comando después se llama graphify con una sola.

Cierra y abre la terminal otra vez. Mismo motivo que antes.
Comprobar
graphify --help

Si lista un montón de comandos, vas bien.

04

Registrar la skill

graphify install

Esto le enseña a Claude Code a usar el mapa. Verás un banner naranja de graphify si funcionó.

05

Traer el mapa y activar los hooks

Entra a la carpeta del repo donde vas a trabajar y corre los dos comandos:

cd "C:\ruta\a\tu\repo"
git pull
graphify hook install
Este paso no se puede saltar. Los hooks de git viven en .git/, que nunca se sube a GitHub — por eso cada persona los instala en su máquina. Lo que instalan es un merge driver: sin él, el día que dos personas modifiquen el mapa el mismo día, git arma un conflicto de 100.000 líneas imposible de resolver a mano.

Hay que repetir este paso en cada repo donde vayas a trabajar:

RepoQué es
GraphBackend
Pagina-web-clientes-finalFrontend
U-Windows-AppCliente de Windows
Comprobar que todo quedó
graphify god-nodes --top 5

Debe listar los archivos más conectados del proyecto. Si los ves, graphify ya funciona — el resto de esta guía es opcional.

Parte 2 — Obsidian

pasos 6–8 · opcional
06

Instalar Obsidian

winget install Obsidian.Obsidian

O descárgalo de obsidian.md si prefieres el instalador normal.

07

Generar la bóveda

Desde la carpeta del repo:

graphify export obsidian --dir C:\mi-vault
Usa una ruta corta, sí o sí. Windows limita las rutas a 260 caracteres, y algunos nodos generan nombres de archivo larguísimos. Con C:\mi-vault funciona; con C:\Users\TuNombre\Documents\Proyectos\... falla con FileNotFoundError a media exportación.

Si trabajas en varios repos, dale una carpeta a cada uno (C:\mi-vault\backend, C:\mi-vault\windows) y luego abre la carpeta padre.

08

Abrir la bóveda

  • Abre Obsidian y elige “Abrir una carpeta como bóveda” — no “Crear”, que haría una vacía.
  • Selecciona C:\mi-vault.
  • Presiona Ctrl+G para la vista de grafo.
Sale todo gris. Es normal: Obsidian no sabe qué significan tus notas. Para darle color, en el panel de la derecha despliega Grupos → Nuevo grupo y escribe path:backend con un color; repite con path:frontend y path:windows.

El día a día

No cambia nada de lo que ya haces. El mapa se mantiene solo.

Cuando haces…Pasa esto
git pullRecibes el código y el mapa actualizado del equipo
Preguntas en Claude CodeConsulta el mapa antes de responder, sin que hagas nada
git commitEl hook actualiza el mapa con tus cambios, automáticamente
git pushTu mapa actualizado sube para los demás

Y si prefieres preguntar desde la terminal:

graphify query "como funciona la autenticacion"

Mantenimiento — una vez por semana

El hook mantiene el mapa al día solo, pero hay una cosa que no mantiene: los nombres de los grupos.

Cada grupo del mapa tiene un nombre en castellano llano — “Exportación de notas clínicas”, “Motor de voz”. Esos nombres los escribe una IA. Pero la reconstrucción automática del hook es rápida y gratis justamente porque no usa IA: recalcula los grupos y, al no poder nombrarlos, los rebautiza con el archivo más grande de cada uno.

O sea, con el tiempo los nombres se degradan así:

Nombre buenoEn qué se degrada
Superadmin Dashboard & Exportsupabase/server.ts
App Layout & Login AuthuseStore
Clinical Audit UI Panelsnote-review.ts

Sigue funcionando igual para buscar y consultar — solo se vuelve más difícil de leer. Para devolverles los nombres:

graphify label . --backend claude-cli --batch-size 20
El --batch-size 20 importa. Por defecto graphify manda 100 grupos en una sola consulta al modelo, y los nombres salen genéricos. Con 20 son más consultas y tarda más, pero cada grupo se analiza con contexto real.

Este comando sí necesita Claude Code autenticado (claude auth login) o una API key. Basta con que una persona del equipo lo corra y haga commit — a los demás les llega con git pull.

Si algo falla

Estos son los errores reales que aparecieron al montarlo. Si te topas con alguno, ya está resuelto.

ErrorSolución
graphify no se reconoce Corre uv tool update-shell y abre una terminal nueva
uv trampoline failed to canonicalize script path La instalación quedó a medias. Reinstala con uv tool install graphifyy --force
Conflicto de git en graph.json Te faltó el paso 5. Corre graphify hook install en ese repo
FileNotFoundError al exportar a Obsidian Ruta demasiado larga. Exporta a C:\mi-vault (paso 7)
La exportación se queda pegada o falla con imágenes Agrega --code-only para saltarte documentos e imágenes

Qué no hacer

  • No edites graphify-out/ a mano — se regenera solo y perderías el cambio.
  • No escribas notas propias dentro de la bóveda generada — la próxima exportación las borra. Si quieres notas tuyas, ponlas en una subcarpeta aparte que graphify no toque.
  • No te saltes graphify hook install — es lo único que evita los conflictos de merge.

¿Necesitas API key o cuenta de Claude? Para consultar el mapa, no. Ya viene hecho en el repo. Solo haría falta si agregas documentación .md nueva y quieres meterla al mapa — ahí sí se necesita Claude Code autenticado (claude auth login) o una API key con saldo.
